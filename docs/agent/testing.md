# 테스트 규칙 (필수)

- **새 service 로직에는 단위 테스트가 필수다.** 버그 수정 시에는 회귀 방지 테스트를 우선 추가.
- 스타일: JUnit5 + `@ExtendWith(MockitoExtension.class)` + `@Mock`/`@InjectMocks`,
  **AssertJ**(`assertThat`) + **BDDMockito**(`given`/`then`).
- 테스트 메서드명은 기존처럼 **한글**로 상황을 서술 (예: `잘못된토큰_SecurityException`).
- given/when/then 구조를 유지.

## 호출 제한·캐시 변경 테스트

MCP 도구의 호출 제한, 결과 캐시, 동시 실행 제한을 추가·수정할 때는 아래 계약을 테스트로 고정한다.

- **전역 도구 한도**: 인증 주체가 없는 동안에는 `toolName`별 모든 요청이 하나의 quota를 공유한다. `serverName`을 바꿔도 한도를 우회할 수 없다.
- **경계값**: 설정된 허용 횟수까지는 통과하고, 다음 요청부터 거절한다. 짧은 burst와 refill도 검증한다.
- **거절 응답**: MCP 도구 응답에서 실제 조회 없이 재시도 가능 시각을 안내하는지 검증한다.
- **중복 요청**: 동일 도구·파라미터의 동시 요청은 한 번만 실제 조회하고 결과를 공유한다. 파라미터가 다르면 공유하지 않는다.
- **시간 의존성**: `System.currentTimeMillis()`를 테스트 대상에 직접 박지 말고 `Clock` 또는 주입 가능한 시간 공급자를 사용한다.
- **저장소 구현체**: 메모리 구현은 단위 테스트, Redis 등 분산 구현은 동일 계약 테스트를 공유한다. 실제 Redis 연결이 필요한 테스트는 기본 단위 테스트와 분리한다.
